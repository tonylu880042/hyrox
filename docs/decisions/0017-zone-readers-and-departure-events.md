# ADR 0017 — 一站一台區域讀取器：離開事件與終點線

- 狀態：**主機端與模擬器已實作**（2026-10-08）；韌體待實作，上行格式需韌體團隊確認
- 日期：2026-10-08
- 影響範圍：MQTT 上行格式（`docs/event-protocol.md`、`docs/reader-integration.md`）、
  ESP32 韌體、`crates/contract`、`raw_events`（migration）、`crates/domain`
  （新讀取器模式、完賽規則）、ADR 0016 的起終點墊語意
- 不影響：判重鍵、ACK 協定、edge journal、`detected_at` 為官方時間的原則

## 背景（使用者確認，2026-10-08）

- 全場 **9 台** RFID 讀取器：**8 個站各 1 台 + 起終點墊 1 台**。
- 站點讀取器的天線**照整個站區**：選手運動時一直在讀取範圍內。
- 進站與出站都由同一台讀取器判斷，**站內時間由主機計算**。
- 結果以**衝過起終點墊**為準（不是拋藥球出站）。

現行協定做不到：ESP32 只在標籤**出現**時送事件（CLAUDE.md 14）。選手進站送一次，
之後一直在場、全部被抑制；離開時 ESP32 不送任何東西。主機永遠收不到出站。

## 提議

### 1. 上行格式：選填欄位 `presence`

```json
{ "device_id": "a4cf128b3d91", "reader_id": "rfid-01", "boot_id": 18, "sequence": 10383,
  "presence": "DEPARTED",
  "tag_id": ["E280117000001234"], "detected_at": 1787734991200, "uptime_ms": 552730 }
```

- `presence` 為 `"ARRIVED"` 或 `"DEPARTED"`；**省略時視為 `ARRIVED`**。現有韌體不需改動
  即可繼續運作，門口型與閘門型讀取器也不受影響。
- **DEPARTED 的時機**：標籤缺席超過 `absent_timeout` 而被 re-arm 的那一刻，ESP32 送出。
- **DEPARTED 的 `detected_at` = 該標籤最後一次被看到的盤點輪次時間**，不是判定缺席的時間。
  兩者相差 `absent_timeout`（3–5 秒），用後者會讓每一站的站內時間都多算這段。
- 最後一次被看到的輪次相同的標籤，合併成一則訊息（與 ADR 0014 的「一輪一則」一致）。
- 自己的 `sequence`，走同一個 journal 與 ACK；判重鍵不變。

### 2. 主機：新讀取器模式 `ZONE`

| 收到 | 選手狀態 | 解讀 |
|---|---|---|
| ARRIVED | 站外 | 進站（照常計算前一段跑步） |
| ARRIVED | 在另一站內 | 進站 + 前一站出站未讀（ADR 0016） |
| DEPARTED | 在這一站內 | 出站，時間 = 最後被看到的時刻 |
| 其他 | — | 記錄為 `PASSED`，不改狀態 |

`raw_events` 新增 `presence` 欄位（migration），原始事件仍不可修改。

### 3. 抖動防護（使用者同意，預設 15 秒，每台讀取器可設定）

區域天線有兩種抖動：

- **短暫掉出範圍**：選手在站內，被身體或器材擋住超過 `absent_timeout` 又回來，
  會產生「出站 → 再進站」。**對策**：同一站出站後 15 秒內又在同一站 ARRIVED，
  視為一直在站內——撤銷那次出站，而不是開一趟新的。
- **路過站區邊緣**：跑步路線經過站區時被讀到，會產生「進站 → 出站」。**對策**：
  停留不到 15 秒的一趟，不算到站。

兩者都需要「撤銷先前的解讀」：新增一種解讀事件，重播時由 `apply` 處理，
與即時路徑相同，維持重播的確定性（CLAUDE.md 21）。原始事件與被撤銷的解讀都保留，可稽核。

### 4. 終點線：起終點墊不再兼任拋藥球出站

ADR 0016 的「墊子關閉其登記站點」改為可設定。對 8 站 + 墊子的配置：

- 出發前讀到 → 起跑（不變）。
- 已完成課表所有站點、在站外時讀到 → **衝線**，完賽時間 = 這次讀取。
- 其他 → `PASSED`（不變）。

`CourseComplete` 的結算點從「最後一站出站」改為「完成課表後的第一次衝線」。
這推翻了 2026-08-28 的決議（最後一站出站即成績），**以本 ADR 為準**。

## 現場必須滿足的條件（不由程式保證）

1. **相鄰站區的讀取範圍不能重疊**，跑道也不能穿過站區的讀取範圍。重疊會讓一位選手
   同時在兩站「進站」。須在現場用 RSSI 門檻、功率與天線角度調整（`reader-integration.md`）。
2. 站區讀取器的 `absent_timeout` 建議比閘門型長（例如 8–10 秒），減少短暫掉出範圍。
   實際值須在現場量測。
3. 起跑前選手必須在起終點墊讀取範圍外（同 ADR 0016）。

## 考慮過的替代方案

- **改用門口型天線**（只照入口，進出走同一門）：不需改協定，現有 TOGGLE 即可。
  但進站漏讀時，出站會被當成進站，且系統察覺不到。使用者選擇區域天線。
- **主機自己推算離開**（一段時間沒收到就算離開）：做不到。ESP32 在選手在場時不送事件，
  「沒收到」與「還在場」在主機看來是同一件事。

## 可攜性

協定與 domain 變更，不涉及作業系統 API；macOS 與 Linux 行為相同。
