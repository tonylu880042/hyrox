# HYROX 訓練與競賽應用系統｜影片劇本審閱稿

版本：2026-09-09 · V2 · 純軟體模擬與畫面說明文字 · 待審閱

本稿依目前專案介面與操作程式設計，尚未進行錄影前的全流程實機彩排。用途是先確認敘事、內容比重與分鏡，不是逐秒字幕定稿。既有兩分鐘影片文件保留作為歷史參考。

## 一、整體方向

製作兩支可以獨立觀看的操作情境影片，每支約 4 分鐘：

- **一般團課篇｜從報到到下課，教練掌握每個人的訓練進度。** 著重排課彈性、手環綁定、即時進度、暫停恢復與課後回顧。
- **競賽篇｜從選手報到到完賽，讓現場進度與成績清楚可見。** 著重賽程設定、身分綁定、分站計時、完賽更新及排名展示。

目標觀眾先以場館經營者、教練與賽事工作人員為主。敘事以「現場怎麼用」帶出產品價值；全片採真實系統螢幕錄影，使用虛構人員與模擬感應事件，不需要真人、實體手環、讀卡機、平板或場館拍攝。運動過程由進出站、持續計時與進度更新呈現。

**配對的暫定定義：學員／選手與 RFID 手環綁定。** 本稿未將配對解讀為雙人組隊、程度分組或設備配對。若需要上述功能，應另調整內容，並先確認產品支援程度。

共同故事線：教練準備 → 報到辨識 → 手環配對 → 開始運動 → 現場監控 → 結束與回顧。

呈現原則：每個關鍵操作都拍到「操作前 → 點擊／感應 → 系統回應」。讓觀眾知道畫面為什麼變化。以畫面說明文字為主要解說，無旁白也能理解；下列口白保留為選配旁白參考。實際上板文字見第八節，依操作結果出現，不把整段口白同時貼上畫面。

## 二、共同角色與錄製情境

| 模擬角色／工具 | 畫面任務 |
| --- | --- |
| 教練操作視角 | 在瀏覽器實際排課、設定規則、開始、暫停及恢復，查看課後紀錄 |
| 報到操作視角 | 實際查找報名編號、建立人員、將模擬手環綁定到人員 |
| 四位虛構學員／選手 | 一人為主角，完整追蹤其報到、綁定、進出站與成績；另外三人呈現不同進度 |
| 電腦與系統 | 錄製報到頁、教練頁、大螢幕頁與成績頁；背景工具送出模擬感應，工具不入鏡 |

主角在所有鏡頭維持相同姓名、號碼與模擬手環識別。所有手環及進出站感應均由軟體模擬，畫面保留「示範資料・感應事件模擬」角標。提示文字與箭頭為影片後製標註，不改成產品本身的按鈕或通知。

## 五、動態錄影與剪輯要求

1. **真實連續操作。** 核心段落直接錄製可操作系統；靜態截圖的推近只能當補充，不能替代點擊、感應、計時或榜單變化。
2. **三組必要連動鏡頭。** 手環感應與報到頁、教練開始／暫停與大螢幕、最後出站與成績更新。以瀏覽器雙視窗同步錄製或後製分割畫面，保留實際回應順序。
3. **一個主角貫穿。** 主角進站時放大其卡片，完成後跟到同一姓名的成績；保持主角姓名、號碼及事件一致。
4. **關鍵結果留 2–3 秒。** 綁定成功、課程規則、分段新增、完賽及名次都需讀得清楚。暫停鏡頭至少連續保留 3 秒，無剪接。
5. **運動過程可濃縮，因果不要跳過。** 至少一站完整交代進入、運動、離開及系統反應；其餘站用蒙太奇。課程大幅跳時加上「課程片段／時間快轉」字卡，不把快轉當系統正常計時。
6. **清楚呈現來源。** 以背景模擬事件驅動真實 UI，畫面加註「示範資料／模擬感應」。工程終端機不作為主要產品操作畫面。
7. **交付方向。** 先以 16:9、1080p、30fps 為成片規格；原始螢幕錄影建議 1440p 以上。保留無字幕母檔、字幕檔與剪輯工程；每段前後多錄 5 秒。
8. **字幕與聲音。** 繁體中文，單次一個重點；字幕避開按鈕、時間及排名。保留感應與成功提示音，背景音樂維持低音量；旁白為選配。

## 六、功能邊界與錄前彩排

本稿已比對目前報到頁、課表頁、排行榜與個人成績頁的程式；下列細節須按實際畫面錄製：

- 目前報到介面是「待綁手環 → 選擇人員 → 點擊綁定」。不沿用舊手冊所述「先點姓名，刷卡便自動完成」的演法。
- 競賽需同時選定競賽模式與完成全程規則；團課本稿選時間到結束。不能只切模式便宣稱必然有排名。
- 不將課堂總時鐘啟動說成所有選手個人成績同時起算；個人時間依系統實際感應與計時規則呈現。正式錄影前彩排確認起算與完賽顯示。
- 手環感應用來記錄身分及進出站，不宣稱自動辨識運動姿勢、重量或完成次數，也不加入自動判罰的敘事。
- 本稿不安排雙人自動配對、分組／年齡篩選、心率、歷史進步比較或自動配速建議；目前尚未確認其完整可操作流程。
- 異常處置有後端能力，但尚未確認教練可用的完整圖形操作介面，因此不安排「教練點一下改判」主鏡頭。需要時另加操作教學附篇，完成介面驗證後再定稿。
- 個人成績與分享卡已有介面實作，可列入腳本；錄前確認主角資料正確、分段可展開與卡片可生成。原生分享依裝置支援，不將開啟預覽說成已發布社群。
- 報名編號輸入作為穩定的主流程；攝影機掃 QR 的鏡頭，需先驗證實際瀏覽器與安全連線環境。
- 外網中斷、設備重啟與資料復原留給後續可靠性影片，本次主片保持日常功能與操作焦點。

錄前彩排通過條件：兩種活動均能建立 → 四人可報到綁定 → 主角連續兩站顯示正確 → 團課可暫停恢復並結束 → 競賽可由末站出站觸發完賽及排名 → 個人成績與總表對得上。

## 七、本輪審閱重點

請優先審閱以下四點；未定部分暫依本稿建議：

1. **配對定義：** 是否就是「人員與手環綁定」，還是也需要呈現人員分組／雙人配對？
2. **片長與用途：** 是否接受各 4 分鐘的完整流程展示？若主要用於短版提案，可在完整素材之外各剪一支 60–90 秒精華。
3. **拍攝形式：** 已改為純軟體模擬展示，不需要真人或感應設備。
4. **聲音形式：** 以畫面說明文字獨立解說，旁白選配；上板文案見第八節。

## 八、影片說明文字與上板規則

### 8.1 三種文字層級

- **段落標題：** 左上顯示目前步驟，例如「03 手環配對」，切換段落時出現，幫助觀眾定位。
- **操作說明：** 畫面下方固定說明區，一次一至兩行，說明正在做什麼與結果。每則約 4–7 秒，長句至少 6 秒；以實際點擊及結果出現時點對齊，不固定平均切秒。
- **局部提示：** 按鈕、計時或名次旁的小標籤與細框，例如「選擇學員」「綁定成功」「分段新增」。一次只突出一個重點；成功文字須等系統真的成功後才出現。

1080p 建議段落標題 40–48px、操作說明 32–38px、局部提示 28–32px，使用繁體中文黑體、深色底白字，重點可用系統黃色。畫面周圍預留約 5% 安全邊界；說明區不得遮住按鈕、時間、姓名、名次或系統原有通知，必要時將系統畫面縮入上方區域。說明框採一致樣式，讓觀眾辨識為影片註解。

全片角標：「示範資料・感應事件模擬」。片頭另顯示約 5 秒：「以下以模擬學員與感應事件，展示系統實際操作流程。」時間快轉處另加「流程節錄・時間快轉」，暫停與恢復鏡頭不快轉。

### 8.4 說明文字驗收

- 每個關鍵點擊與模擬感應，都有簡短說明，且結果字卡不提前出現。
- 關閉聲音觀看，仍能理解報到、配對、進出站及成績更新的完整流程。
- 不展示程式指令、模擬控制工具或資料庫內容；模擬來源以角標說明即可。
- 字卡不虛構 UI、不遮擋關鍵內容，不用後製數字代替系統真實結果。
- 兩片沿用同一字型、位置、色彩與提示方式；團課不套用競賽排名敘事。
